# 07 — Development Workflow

## Repository layout

```
docs/              design docs and ADRs (this folder)
control-plane/     FastAPI server (Python)
connector/         customer-side connector (later)
.github/workflows/ CI
```

## Branches

Branch
Purpose

`main`
Production-ready. Protected. Only merges from `dev`.

`dev`
Integration branch. Protected. Features merge here via PR.

`feat/<short-name>`
New feature, branched from `dev`

`fix/<short-name>`
Bug fix, branched from `dev`

`docs/<short-name>`
Documentation only, branched from `dev`

Flow: `feat/*` → PR → `dev` → release PR → `main`.

## Commits

Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`, `ci:`.
Example: `feat: add tenant member invitation API`.

## Pull requests

- Small and focused; one concern per PR.
- CI must be green; at least one review before merge.
- Update docs in the same PR when behaviour, schema, permissions or protocol change.

## Rules

- **No manual database changes.** Every schema change is an Alembic migration.
- Never edit a migration that has been merged; add a new one.
- Every migration must upgrade **and** downgrade cleanly (CI checks this).
- Never commit secrets. `.env` is ignored; `.env.example` documents variables.

## Local setup (Windows)

Prerequisites: Git, Python 3.12, [uv](https://docs.astral.sh/uv/), PostgreSQL 16+.

1. Create the local databases and user once (as the `postgres` superuser):

```
CREATE ROLE zipzy LOGIN PASSWORD 'change-me-local';CREATE DATABASE zipzy_dba OWNER zipzy;CREATE DATABASE zipzy_dba_test OWNER zipzy;
```
2. Install and run:

```
cd control-planecopy .env.example .env      # then edit DATABASE_URL if neededuv syncuv run alembic upgrade headuv run uvicorn app.main:app --reload
```
3. Open http://127.0.0.1:8000/docs

## Everyday commands (from `control-plane/`)

Task
Command

Run tests
`uv run pytest`

Lint / format
`uv run ruff check .` / `uv run ruff format .`

Type check
`uv run mypy app tests`

New migration after changing models
`uv run alembic revision --autogenerate -m "what changed"`

Apply migrations
`uv run alembic upgrade head`

Roll back one migration
`uv run alembic downgrade -1`

Always read an autogenerated migration before committing it.

## Tests

- Run against a real PostgreSQL (`zipzy_dba_test`), never SQLite — constraints, RLS and
types are part of what is tested.
- Each test runs in a transaction that is rolled back.
- Migration tests: full downgrade/upgrade roundtrip and "models match migrations" check.

## CI (GitHub Actions, on every PR and push to `dev`/`main`)

1. Install dependencies with uv (locked).
2. `ruff format --check`, `ruff check`.
3. `mypy` (strict).
4. `pytest` against a PostgreSQL service container.
5. Build the Docker image.
